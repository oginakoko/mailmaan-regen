# Soko demo store — example implementation

Live: `https://mailmaan-regen.vercel.app/demo/soko` (one product,
no payment, real emails). This is the reference for "how do I connect
my app's happenings to Mailmaan": signup- and purchase-style events,
AI-made templates reused per send, per-user variables, and timelines.

## What it demonstrates

| Your app concept | Soko equivalent |
|---|---|
| User signs up | `user.signed_up` → welcome template |
| Customer pays | `order.paid` → AI receipt template |
| Order tracking | `order.packed/shipped/out_for_delivery/delivered` → AI templates |
| Personal follow-up | `order.thank_you` → AI template with per-order quote + products |
| Template authoring | `POST /v1/templates/generate` with brief + required variables |

Every template in the demo was generated by the AI from a one-line
brief, reviewed, published once — then reused for every order. The
thank-you is unique per order because the *event data* carries the
buyer's products and a stable-per-order quote, not because the AI
runs per send (slow, costly, non-deterministic).

## How it works (code map)

- `src/app/demo/soko/page.tsx` — storefront + checkout server action.
  Checkout inserts `demo_orders`, fires `order.paid` through the
  **public API** (`/v1/events` with a project key), redirects to
  tracking. Public form, so it throttles to 3 orders/email/hour.
- `src/app/api/demo/soko/status/route.ts` + `src/lib/demo/soko.ts` —
  stage advancement with **no cron**: the tracking page polls every
  10s; each poll fires due stages (one per minute) with stable
  external ids (`soko-demo/<order>/<stage>`), so restarts and
  double-visits never double-send. Run outcomes ride back so failed
  emails render red, never green.
- `src/app/demo/soko/track/[orderId]/` — tracker UI + the
  brief-the-AI finale: generate (constrained variables) → human
  preview → publish + direct send.
- `supabase/migrations/20261027000900_demo_orders.sql` — orders
  table, service-role only.
- `examples/soko-store/` — the same integration as a standalone SDK
  client (`signup`/`checkout`), runnable with `npm run demo`.

## Copy it for your app

1. Create a project, connect its mailbox, generate + publish one
   template per email type (dashboard or `generate_template` MCP tool).
2. Create one workflow per event: trigger name, recipient path,
   variable mappings from event `data`.
3. From your server, `POST /v1/events` on signup/purchase/shipment
   with a stable external `id` and all template variables in `data`.
4. Read timelines (`GET /v1/messages/:id`), sync upstream state
   (`POST /v1/messages/:id/sync`), diagnose from evidence.

Full API walkthrough: [developer guide](/docs/developer-guide).
